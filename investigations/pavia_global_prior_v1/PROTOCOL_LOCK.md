# Pavia global-prior premise: staged protocol lock

This document fixes the evaluation plan before any new Pavia target classification metric is inspected. Houston is development evidence. The first Pavia result will test the premise, not select a Houston-derived hyperparameter. Once Pavia labels inform a method choice, a third scene is needed for final confirmation.

## Stage 1: reproduce the upstream local baseline

- Task: Pavia University source → Pavia Centre target, seven shared classes, 102 bands. Start with upstream seeds **1622, 1322, 1256**, in that order; expand to the full official ten-seed list for any paper table.
- Mirror `MLUDA_up.py`, `config_UP2PC.py`, `utils.load_data_pavia`, `utils.get_sample_data`, `utils.get_all_data`, and `UtilsCMS.ILDA`: per-scene per-band z-score; ILDA PCA=2 and radius=0.00009; 180 source training centers/class; 11×11 zero-padded patches; batch=32, shuffle and `drop_last=True`; 100 epochs; SGD constant LR=0.001, momentum=0.9, weight decay=0.0005, recreated optimizer per epoch; original full MLUDA loss and augmentation; final-epoch checkpoint.
- For exact upstream sample ordering, the archived code reads Pavia target GT to identify `GT>0` evaluation centers and shuffles them classwise. This reveals center membership/order to the protocol but must never feed class labels into losses, checkpoint choice, prior fitting, or method choices. Record this restriction explicitly; it is a limitation of the benchmark protocol, not an unlabeled dense-scene deployment simulation.
- Use the upstream final-epoch paired inference forward with the saved final source minibatch, batch 32 and `drop_last=True`. OA follows the upstream `correct / full official target-center count`; AA/Kappa/recalls use the evaluated confusion matrix. Save input/preprocessing/split/code/checkpoint hashes and all raw probabilities before any audit. Compare the ten-seed result to the paper's Pavia 91.26% OA / 92.70% AA, and investigate a ~70% reproduction before proceeding to any new-method claim. Three seeds are a technical gate, not a substitute for the paper's ten-seed mean.

## Stage 2: teacher and premise diagnostic

- Build a **new 102-channel** HyperSIGMA teacher from the original pretraining weights, using 33×33 patches from the Pavia images after the upstream independent per-scene per-band z-score and **before ILDA**. Use the identical 180/class source train centers as the paired MLUDA seed. Reserve the first 30/class from each class's remaining official source permutation for source-only validation. Mirror the already-used Houston teacher schedule: 20 stage-1 epochs and 20 full fine-tuning epochs, source-val accuracy selecting the first maximum within each stage and the better of the two stages (tie → stage 1). The Houston 48-channel fine-tuned model is not used. No Pavia target GT selects teacher stage or checkpoint.
- Freeze teacher probabilities on the same official target centers as local predictions. Define `pi_H = mean_i p_H(i)` over all available official centers, including rows omitted by final `drop_last`; preserve the exact center order and hashes. Freeze local raw and `lambda=1` soft-KL probabilities and hard-prior projection as predeclared diagnostic controls, without target-GT tuning.
- After every prediction file is frozen, perform a single GT audit: local/teacher pointwise OA and AA, true target marginal, total variation and classwise prior errors, OA/AA/Kappa/seven recalls for raw/soft/hard, wrong→correct and correct→wrong transitions, and source/teacher costs. Report all seeds and paired differences. A useful premise signal requires better teacher-prior marginal error than the local marginal on most seeds **and** evidence that global correction has both benefits and identifiable class-specific harm. These are descriptive gates, not a method result.

## Stage 3: method decision

If Stage 2 supports the premise, design one label-free reliability/allocation mechanism using source labels and unlabeled target predictions only. Predeclare its rule and test against fixed soft-KL, hard correction, local model, and full MLUDA on paired seeds. Do not tune using Pavia target GT and then report Pavia as independent validation. If Stage 2 fails, revise or stop this particular global-prior story; do not change coefficients until Pavia target scores look favorable.
